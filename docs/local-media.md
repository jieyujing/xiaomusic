# miniFNOS 本地媒体限定部署

此分支只允许播放 `/vol2/1000/music` 内现存的媒体文件，包含子目录。
支持的扩展名沿用 `SUPPORT_MUSIC_TYPE`。该路径写在
`xiaomusic/local_media.py` 中，不接受网页设置覆盖。
媒体服务地址固定为 `http://192.168.100.99:8090`，网页修改 hostname
不会使外部服务器获得媒体播放授权。

扫描、生成 URL、向设备发送播放指令以及 HTTP 文件读取均检查真实路径。
越界软链接、目录穿越、非媒体文件、外部链接和代理链接会被拒绝。
目录扫描不跟随目录软链接，避免越界和循环。

在线歌单、下载、上传、Python 指令插件、原始播放调试接口、网页自更新和
目录外系统提示音不可用。Edge TTS 和生成临时媒体的格式转换也已关闭。
媒体按原文件提供，设备必须支持对应格式。播放控制、收藏及本地歌单保留。

Docker 将宿主机 `/vol2/1000/music` 只读挂载到相同容器路径。
配置、标签缓存和临时工作目录放在独立的 `conf` 挂载中。
目录不存在时部署失败，不自动创建空媒体目录。

部署文件：

- `deploy/Dockerfile.local-media` 基于已固定摘要的官方运行环境构建本分支。
- `deploy/minifnos.compose.yaml` 应复制到 NAS 原部署目录作为
  `docker-compose.yml`，并将 image 改为本次构建的唯一标签。
- 替换前备份原 Compose 和 `conf`；音乐文件不需要移动或复制。
- 构建后先运行 `test/test_local_media.py`，再执行
  `docker compose up -d --wait`。

此策略限制 XiaoMusic 自身的媒体播放，无法阻止小爱音箱固件自行响应其他
小米云端指令。实际音箱播放仍需要有效的小米登录及设备连接。

## 语音播放与随机回退

收到“播放…”“继续播放…”“播放歌曲…”“播放故事…”“讲个故事”等媒体请求时，按标题查找本地媒体，
随后用替换队列请求直接接管。找不到时，从整个本地曲库中随机
选择一个当前仍在授权目录内的文件。找到多个候选时直接随机选择，不等待
用户再回答“第几个”。曲库为空时停止播放，不下载、不回退到云端音源。

本地播放统一使用已在 LX06 实测的 `player_play_music` / `REPLACE_ALL`
请求，替换设备播放队列。使用 SDK 固定元数据，不按歌名查询云端 audio ID；
播放流仍必须通过授权目录校验。

语音轮询保持开启，间隔为 1 秒。暂停接口失败时仍尝试停止；强制停止模式
不依赖可能失败的播放状态查询。控制面板命令和明确的播放列表命令保留
原路由。尚未启用的 Agent 开发代码不参与此次部署。

原厂 LX06 通过云端对话记录接受接管，音箱可能在记录到达之前先开始播放
内置音源。本策略保证收到媒体指令后的本地处理路径，无法从原厂固件层面
保证内置音源完全不启动。不得把模拟测试当成实际语音或音频输出验收。

2026-10-20 实机验证：用户确认通过替换队列请求下发的 NAS 本地
《勇气大爆发 [AI翻唱]》已经可听见。该验证针对播放接口；自动语音接管
仍须与识别、轮询及回退路径共同验收，不能以接口返回码代替听感。

最终版 `voice-local-c7c3bc15e93e` 部署后，用户再次说“继续播放植物大战僵尸故事”，
确认音箱已转为本地歌曲。35 项回归测试通过，实际 1,387 项曲库的四条
模拟请求均只选择授权本地文件；模拟测试的设备 I/O 被替换，不计作听感验证。

## 语音接管延迟

原播放链路在语音入口和 `_playmusic` 各串行发送一次暂停与停止，
一次正常接管共四次额外云端请求。现由 `REPLACE_ALL` 本身替换播放，
只在替换失败或曲库为空时单独停止；用户主动停止命令保留。
完整文件名命中直接返回；纯函数繁简转换使用最多 8,192 项的缓存，
保留原候选及阈值规则。云端记录到达前的等待不受上述优化控制。

性能对比（miniFNOS、2,359 项曲库）：旧日志的 9 次语音接管从记录收到
到播放提交为 5–9 秒，每次均有两次暂停和两次停止。优化后完整文件名
查询不足 0.1 毫秒；缓存随扫描预热后，“晴天”首次/中位查询约 23.8 毫秒，
不存在的故事查询首次约 20.6 毫秒、中位约 21.0 毫秒。基准为本地搜索，
不包含云端记录延迟和音箱实际出声时间。39 项回归测试通过。

## 本地匹配与别名

播放匹配按强度分层，命中较强层后不补入较弱候选：

1. 完整文件名（可带扩展名）。
2. 自定义别名、规范化后的完整名、清理后的歌名、歌手加歌名。
3. 关键词包含匹配，只保留覆盖比例最高的候选。
4. 本地目录或专辑名匹配。
5. 文字相似度匹配，只保留最高分并列候选。

规范化包含繁简转换、英文大小写、全角字符和标点空白处理。
自动别名保留原名，并清理曲目前缀（例如 `01-03 `）以及括号内的
AI 翻唱、Live、伴奏等版本标记；显式说出版本时仍能区分。
括号里的译名也可作为别名，`Library/Albums/歌手/专辑` 结构提供歌手信息。
例如只说“晴天”不会混入“晴天娃娃”；说“晴天 Live”只匹配现场版。
同层最高强度仍有多个版本时沿用随机选择；完全未命中仍随机播放本地文件。

少于 4 个规范化字符的查询不作近似错字猜测；更长查询的模糊阈值为
`max(fuzzy_match_cutoff, 0.72)`。这是字符相似度分数，不是正确率或模型概率。
不提供拼音、歌词或语义理解。

可以在 NAS 的 `conf/music_aliases.json` 自定义口令别名，值必须是现有曲库
里的完整名称，不含扩展名；支持字符串或字符串数组。例如：

```json
{
  "周董的晴天": "周杰伦-晴天",
  "小朋友的歌": ["勇气大爆发 [AI翻唱]"]
}
```

保存后刷新曲库生效。不存在的目标和外部 URL 不会成为候选；JSON 无效时
保留自动文件名匹配。该文件不包含账号信息，也不会发送给外部模型。

2,359 项实际曲库回放：`晴天` 返回 3 个对应版本，排除 `晴天娃娃`；
`勇气大暴发` 返回 `勇气大爆发 [AI翻唱]`；`周杰伦的晴天` 只返回 2 个
周杰伦的本地版本。精确别名中位查询约 0.1 毫秒，错字查询约 23.6 毫秒，
未命中的故事查询约 22.1 毫秒。55 项回归测试通过，包括别名刷新和无效
JSON 回退；以上回放均没有实际控制音箱。

## 询问当前歌名

“这是什么歌”“这首歌叫什么名字”“当前播放歌曲名”“播放的是什么歌”
等问句优先于播放请求识别，避免把问题当作新歌名而触发随机换歌。
回答读取 XiaoMusic 的 `is_playing` 和 `cur_music`，并再次验证对应文件属于
授权目录；已停止或文件不可用时回答“当前没有在播放本地音乐”。

仅此明确的状态查询通过已登录的 MiNA `mibrain.text_to_speech` 原生播报。
它不启用通用 TTS，不生成媒体文件、不使用 MiIO 的另一套服务登录，
也不主动暂停、停止或从头重放音乐。播报失败只记录错误类型，不让对话
循环退出。该状态属于 XiaoMusic 管理的本地播放，不声称识别固件独立播放
或实体按键引起的所有状态变化。

`now-playing-0e4956024bb3` 部署后，用户确认询问时正确报出“周杰伦－晴天”。
另以相同问句经 `/cmd` 回放，服务记录一次当前曲目询问和一次原生播报提交，
无播报/登录错误；曲目保持相同，应用进度由 63.1 秒增至 63.7 秒，没有从头
重播。该接口回放与用户听感是分别取得的证据，不等同于捕获了同一次云端语音记录。
60 项回归测试通过。
